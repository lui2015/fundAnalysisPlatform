## 1. 背景与目标

### 1.1 背景

买基金的人比买股票的人多，但获得的决策信息质量更差：

- **销售平台的信息是「排行榜导向」的**：把近 1 年涨得最猛的基金推到最前面，用户按榜单买入，往往买在风格最热的位置。
- **关键信息藏在 PDF 里**：基金的真实约束（投资范围、能力圈、风格约定）写在招募说明书与季报里，普通用户不会读。
- **最该关心的维度被忽略**：基金收益的来源是「基金经理 + 策略 + 持仓」，而绝大多数用户只看过去的收益率曲线，不看谁在管、管了多久、赚钱靠什么、回撤有多深、自己能不能拿得住。
- **「拿不住」是散户基金亏损的第一原因**：不是基金不好，是买入时对波动毫无预期。这个维度在现有产品里几乎没有被结构化表达过。

大模型的价值在于把「多源零散数据（净值、持仓、经理履历、季报、公告、费率）」压缩成「一份人类可读、有结构、有依据的分析报告」。而报告怎么组织，决定它是「又一张收益率排行榜」还是「真正帮人做判断的工具」。

### 1.2 产品目标

- **核心目标（诉求一）**：用户输入基金名称或代码，一次点击即可获得一份按**六大板块**组织的 AI 多维分析报告，全流程 ≤ 60 秒。六大板块回答用户真正关心的六个问题：

  1. **总览** —— 一句话，这只基金是什么、现在什么情况？
  2. **好业绩** —— 它到底赚不赚钱、超额收益从哪来、是实力还是运气？
  3. **好舵手** —— 管这只基金的人靠不靠谱、还在不在、忙不忙？
  4. **好体验** —— 我拿着难不难受？最深跌多少、多久能回本、多大概率拿一年是赚的？
  5. **好时机与成本** —— 它现在的持仓贵不贵、规模与限购如何、我要付多少费用？
  6. **风险排雷** —— 有没有我没看见的坑（风格漂移、清盘、经理离任、机构大额赎回……）？

- **核心目标（诉求二）**：**桌面 Web 与移动 Web 双端适配**。桌面端信息密度高、可横向对比；手机端单手完成「搜索 → 分析 → 阅读 → 分享」，图表可触摸交互，不出现需要缩放才能读的内容。
- **合规目标**：全站清晰标注「AI 生成内容，仅供学习与研究参考，不构成投资建议」。**不推荐基金、不预测收益、不给申赎时点建议**（基金销售的合规要求比个股解读更严，见 3.8 与 9）。

> 框架取舍说明：不采用「业绩 / 风险 / 持仓 / 经理…」的专业维度平铺，而采用提问式结构。原因是前者是**分析师的语言**，后者是**用户的决策语言**；同一份数据按后者组织，用户不需要先学会术语就能读懂结论。专业维度不消失，而是作为各板块内部的子模块存在。

### 1.3 为什么是六块，而不是照搬股票的四块

| 差异点 | 个股 | 基金 | 对框架的影响 |
| --- | --- | --- | --- |
| 收益来源 | 公司经营 | **人 + 策略 + 组合** | 必须为「基金经理」单独设板块（③ 好舵手），这是主动基金最大的变量 |
| 用户痛点 | 看不懂财报 | **拿不住** | 必须为「持有体验」单独设板块（④ 好体验），把回撤/修复/正收益概率前置 |
| 「贵不贵」的对象 | 这家公司的股价 | **它持仓组合的估值 + 我付的费用** | ③「好价格」重构为 ⑤「好时机与成本」，含费率与规模容量 |
| 品种异质性 | 基本同构 | 主动权益/指数/债/QDII/FOF/货币**分析口径完全不同** | 必须支持**按基金类型的差异化模板**（附录 C），这是本产品最大的实现复杂度 |

因此：股票的「好生意 / 好价格」→ 基金的「好业绩 / 好舵手 / 好体验 / 好时机与成本」，加上总览与排雷，共六块。

### 1.4 非目标（明确不做）

| 不做的事 | 原因 |
| --- | --- |
| 基金销售、申购赎回、支付、导流开户 | 需基金销售牌照，监管红线 |
| 推荐基金、基金排行榜、「买什么」清单 | 合规红线，本产品只做「看懂一只已指定的基金」（荐基能力已有独立产品 `fundRecommend`，两者定位区分） |
| 收益预测、目标净值、申赎时点提示 | 合规红线，明令禁止预测收益 |
| 组合诊断（我的持仓整体分析） | P2 迭代方向，一期聚焦单只基金 |
| 自营净值数据源、Level-2 数据 | 成本高，一期用公开接口 |
| 社区、评论、UGC | 一期聚焦分析工具本身 |
| 独立 iOS / Android App | 移动 Web 已满足诉求 |

### 1.6 分析框架总览（本文档的主线）

```
                     用户输入：基金名称 / 代码
                               │
                     基金类型识别（权益/指数/债/QDII/FOF/货币）
                               │
               ┌───────────────┴────────────────┐
               │  数据采集 + 指标计算 + 规则扫描   │ ← 确定性代码，不经模型
               │  净值序列·持仓·经理·公告·费率      │
               └───────────────┬────────────────┘
                               │
     ┌──────────────┬──────────┼──────────┬──────────────┐
     ▼              ▼          ▼          ▼              ▼
 ② 好业绩      ③ 好舵手    ④ 好体验   ⑤ 好时机与成本   ⑥ 风险排雷
 能力分 A      舵手分 M    体验分 X    时机成本分 T     风险灯 R
 超额·归因     人·年限·    回撤·波动·  持仓估值分位·    风格漂移·清盘·
 ·同类排名     一拖多      正收益概率  费率·规模容量    离任·集中·赎回
     └──────────────┴──────────┼──────────┴──────────────┘
                               │   （②③④⑤⑥ 并行调用模型）
                               ▼
                 ① 总览（最后生成、最先展示）
        四维雷达（A/M/X/T）+ 风险灯 + 适配画像 + 背离提示
```

**关键约定（贯穿全文档）**

| 约定 | 说明 |
| --- | --- |
| 展示顺序 ≠ 生成顺序 | 总览排在最上方，但依赖其余板块结论，因此**最后生成**；前端先渲染骨架占位，其余板块流式填充，总览最后回填至顶部 |
| 板块正交 | 「好业绩」只谈收益与超额，不谈回撤（那是 ④）；「好体验」只谈波动与持有感受，不评价业绩高低；「好舵手」的数据切片里**不含基金收益排名**，避免「因为涨得好所以经理牛」的循环论证 |
| 风险板块具备否决权 | 排雷不是第六个加分项，而是**减分与警示项**。命中红线时总览必须显式提示，且不允许总览呈现单纯乐观口吻 |
| 每板块可独立降级 | 任一板块因数据源或模型失败，其余板块照常输出（详见 F3-11） |
| 类型自适应 | 板块与子模块的**存在性与权重**随基金类型变化（指数基金不评「舵手」而评「跟踪误差」；货币基金几乎只看「体验+成本+排雷」），见附录 C |
| 不给单一总分 | 只给 A/M/X/T 四刻度 + 风险灯。一个总分会把「好基金 + 高波动 + 已限购」这类最需要被看见的矛盾抹平，也更容易被当作推荐信号 |

## 2. 用户与使用场景

### 2.1 目标用户

| 角色 | 特征 | 核心诉求 |
| --- | --- | --- |
| 基金小白（主要） | 持有 1–5 只，从排行榜或朋友推荐买入 | 用大白话告诉我这只基金是什么、谁在管、会跌多深 |
| 定投型长期持有者 | 有 1–3 年经验，关注回撤与风格 | 我拿的这只有没有变味（风格漂移）、经理有没有换 |
| 进阶投资者 | 会看季报与归因，时间不够 | 帮我把净值、持仓、经理、公告汇总，省 30 分钟功课 |
| 泛财经兴趣用户 | 不一定持有，看热点 | 最近火的这只基金到底怎么回事 |

### 2.2 典型场景

1. **买之前查一查（P0，移动端）**：看到推荐/榜单，手机输入基金名称，先读总览的一句话与四刻度雷达，10 秒知道大概；有兴趣再下滑。
2. **拿不住的时候（P0）**：基金跌了 15%，用户最想知道「这是正常波动还是出事了」，直接跳板块 ④ 看历史最大回撤与修复时长，再跳 ⑥ 看有没有雷。
3. **换人了怎么办（P0）**：收到「基金经理变更公告」，直接跳板块 ③ 看新任经理的年限、代表作、在管规模与风格是否一致。
4. **风格漂移体检（P0）**：长期持有者定期体检，看板块 ⑥ 的漂移检测（合同约定 vs 实际持仓 vs 历史持仓）。
5. **A/C 类怎么选（P1）**：板块 ⑤ 的费率总成本测算，按不同持有期给出成本对比（描述性事实，不作建议）。
6. **同类对比（P1，桌面端）**：把 3–5 只同类型基金放在一起比 A/M/X/T 四刻度与回撤，桌面端表格全列可见。
7. **分享讨论（P1）**：把报告链接发到群里，对方无需登录即可打开只读报告页。
8. **复盘回看（P2）**：对比一个季度前对同一基金的报告，看四刻度与雷点的变化。

> 场景 2/3/4 说明：六板块结构天然支持「跳读」。这是相比大段文字报告的核心体验优势，因此**板块导航必须在双端都随时可达**（详见 4.3）。

## 3. 功能需求

优先级说明：**P0** = 一期必须有，缺失则产品不成立；**P1** = 一期尽量有；**P2** = 后续迭代。

### 3.1 F1 基金搜索与识别（P0）

**用户故事**：作为用户，我想用我记得的任何形式（基金简称、6 位代码、拼音、甚至只记得公司+主题）找到目标基金。

| 编号 | 需求描述 |
| --- | --- |
| F1-1 | 支持输入：6 位基金代码（`161725`）、场内代码（`510300`、`sh510300`）、中文简称（`招商中证白酒`）、模糊简称（`白酒`、`易方达蓝筹`）、拼音首字母（`zsbj`） |
| F1-2 | 输入框实时联想（防抖 300ms），下拉展示：基金简称、代码、基金类型标签（股票型/偏股混合/被动指数/债券/QDII/FOF/货币）、最新净值与日涨跌幅、近 1 年涨跌幅 |
| F1-3 | **同一基金多份额必须显式区分并提示**：A/C/E/I 类、前后端收费、场内 LOF/ETF 与其联接基金。命中同系列多份额时在下拉中分组展示（如「招商中证白酒 A(161725) / C(012414)」），不得自动选择 |
| F1-4 | 支持键盘操作：↑↓ 选择、Enter 确认、Esc 关闭（桌面端）；移动端点击即选中，热区 ≥ 44px |
| F1-5 | 命中多个结果时不自动跳转，必须由用户显式选择，避免分析错标的 |
| F1-6 | 无结果时给出提示与建议（检查代码位数 / 是否为股票代码 / 是否为专户或未支持类型） |
| F1-7 | 支持范围（一期）：境内公募开放式基金与 ETF/LOF（含股票型、混合型、被动指数、债券型、货币型、QDII、FOF）。私募、专户、券商资管、养老金产品不支持；分级基金已退出历史，不支持 |
| F1-8 | 展示最近搜索 10 条（本地存储，可清除），移动端以标签形式一键复用 |
| F1-9 | 首页提供「热门基金」快捷入口（按平台分析次数排序，**不按收益率排序**，避免变成收益排行榜），降低冷启动门槛 |
| F1-10 | 标的解析后需在报告头部固定展示：全称、代码、份额类型、基金类型、成立日、最新规模、基金公司、当前基金经理、业绩比较基准 |

### 3.2 F2 数据获取与指标计算（P0）

数据只有一个目的：喂养六大板块。最后一列标明服务于哪个板块（① 总览 / ② 好业绩 / ③ 好舵手 / ④ 好体验 / ⑤ 好时机与成本 / ⑥ 风险排雷）。

| 编号 | 需求描述 | 服务板块 |
| --- | --- | --- |
| F2-1 | 基金档案：全称/简称、代码、份额类型、基金类型与二级分类、成立日、基金公司、托管人、业绩比较基准、投资范围与约定（招募说明书要点）、申购状态（正常/暂停/大额限购及限额）、赎回状态、最小持有期 | 全部 |
| F2-2 | 净值序列：**单位净值 + 累计净值 + 复权净值**，成立以来完整日频序列（至少近 5 年）；分红拆分记录（用于复权校正） | ②④⑤ |
| F2-3 | 收益指标：近 1 周/1 月/3 月/6 月/1 年/2 年/3 年/5 年/今年以来/成立以来 区间收益与**年化**收益；逐年度收益（含每个自然年，不足半年的区间需标注） | ② |
| F2-4 | 基准与同类：业绩比较基准同期收益、同类基金（同二级分类）平均与中位、同类排名与**分位**（每个区间均需）、逐年度同类排名（用于稳定性判断）、宽基指数（沪深300/中证800/中证全指）同期对比 | ② |
| F2-5 | 超额与归因：相对基准年化超额、信息比率、跟踪误差（指数基金必需）、超额收益的逐年正负分布；简化归因（行业配置 vs 个股选择，数据允许时） | ② |
| F2-6 | 风险与体验指标（确定性计算）：最大回撤及发生区间、当前回撤、回撤修复天数（中位/最长/当前已持续）、年化波动率、下行波动率、夏普比率、卡玛比率、索提诺比率、上行/下行捕获率、月度胜率、最长连续亏损月数、与宽基相关性/Beta | ④ |
| F2-7 | 持有体验模拟（确定性计算）：**滚动持有正收益概率**（任一交易日买入并持有 1M/6M/1Y/2Y/3Y 的正收益比例）与收益分布（P10/中位/P90）；同口径的定投模拟（按月投）结果分布 | ④ |
| F2-8 | 持仓数据：最近 4 期季报十大重仓股（名称/代码/占比/较上期变动）、行业分布（申万一级）、前十大集中度、股票/债券/现金占比、港股通占比、换手率（估算）、持仓重叠度（与上期、与同类） | ②⑤⑥ |
| F2-9 | 风格刻画：基于重仓股的市值暴露（大/中/小盘）、成长价值倾向、行业集中度；与**招募说明书约定范围**及**历史 4–8 期持仓**的偏离度（漂移检测输入） | ②⑥ |
| F2-10 | 基金经理数据：姓名、任职本基金起始日与任职年限、从业年限、任职期间本基金收益与同期基准/同类、在管基金数量（一拖多）与在管总规模、代表作与其历史业绩、是否跨越完整牛熊、历史变更记录、是否新任（< 1 年）、离任公告 | ③ |
| F2-11 | 基金公司维度：公司管理总规模、旗下同类基金数量与整体表现分位、投研团队稳定性（近 2 年经理离任率，可得时）、公司是否有近期监管处罚 | ③⑥ |
| F2-12 | 规模与持有人：最新资产净值、近 8 期规模变化、机构/个人持有比例、单一持有人占比、份额变动（申赎净额估算）、是否 < 5000 万（迷你基）及连续天数 | ⑤⑥ |
| F2-13 | 费率数据：管理费、托管费、销售服务费（C 类）、申购费（含折扣）、赎回费阶梯（按持有期）、指数基金的综合费率；**持有 1 月/6 月/1 年/3 年的总成本测算**（A/C 类对比） | ⑤ |
| F2-14 | 持仓估值透视：按重仓股加权的 PE/PB 及其近 3/5 年历史分位、重仓行业的估值分位与拥挤度（公募配置比例分位，可得时）、场内基金的**折溢价率**与历史分位（ETF/LOF/QDII 必需） | ⑤ |
| F2-15 | 债券型专项：久期、杠杆率、券种结构（利率债/信用债/可转债占比）、信用评级分布与低评级占比、重仓债违约记录、可转债占比与转股溢价 | ②⑥ |
| F2-16 | 公告与事件：近 12 个月公告标题（经理变更、暂停申赎、大额限购、基金合同变更、清算/清盘提示、份额折算、监管处罚、涉诉、评级调整），须能自动归类 | ③⑤⑥ |
| F2-17 | 大盘与市场环境：宽基指数点位与估值分位、市场情绪水位、债市利率环境（10Y 国债）、汇率（QDII 必需）、所属主题赛道位置 | ⑤⑥ |
| F2-18 | 指标计算层（确定性代码，不经模型）：上述全部收益/风险/体验/分位/成本/漂移指标均由此层产出。**所有出现在报告中的数字必须来自此层**，模型不得自行计算或推算 | 全部 |
| F2-19 | 数据来源需在报告中标注（来源名 + 数据时间戳）；净值需标注「净值日期」，持仓需标注「报告期」（如 2026Q2），规模需标注「统计日」。**所有数据必须显示截止时间** | 全部 |
| F2-20 | 缓存策略：净值当日缓存（收盘后更新，≤ 4h）；持仓/规模按报告期缓存（季度）；经理与档案 24h；公告 ≤ 30min；费率 7 天。缓存命中不计入大模型调用配额 | 全部 |
| F2-21 | 任一数据源失败时降级而非整体失败：受影响的**子模块**标注「数据暂不可用」，所属板块继续输出，并在板块头部标记「数据完整度 N/M」 | 全部 |
| F2-22 | **成立不足 6 个月的基金**：不展示区间收益排名（合规要求），只展示成立以来净值走势与风险提示；不足 1 年的基金在「好业绩」板块显式标注「业绩期过短，结论参考价值有限」 | ②⑥ |

### 3.3 F3 六大板块 AI 分析（P0，产品核心）

**用户故事**：作为用户，我不想看一堆专业维度罗列，我想按顺序知道：这基金啥情况 → 赚不赚钱 → 谁在管 → 我拿着难不难受 → 现在贵不贵要花多少钱 → 有没有坑。

#### 3.3.1 板块①：总览（总结性分析）

**要回答的问题**：这只基金现在整体是个什么情况？如果只让我读 10 秒，我该知道什么？

| 编号 | 需求描述 |
| --- | --- |
| A-1 | **一句话定性**：≤ 45 字，说清「什么基金 + 谁在管 + 当前处于什么状态」。例：「白酒主题被动指数基金，跟踪误差正常，持仓估值处于近 5 年 31% 分位，历史最大回撤 51%」 |
| A-2 | **四刻度 + 风险灯**：能力分 A、舵手分 M、体验分 X、时机成本分 T（各 0–100）与风险等级 R（红/黄/绿），以**四维雷达图 + 风险灯**呈现，是报告的视觉锚点 |
| A-3 | **适配画像（本产品差异化输出）**：以描述性语言给出「这只基金的历史特征意味着什么样的持有条件」，如「历史最大回撤 51%、回撤修复中位 14 个月；滚动持有 1 年正收益概率 58%，持有 3 年为 81%」。**必须是历史事实陈述，禁止出现「适合你」「建议持有 X 年」等建议性表述** |
| A-4 | **3–5 条结论要点**：每条对应一个后续板块，点击锚点跳转。要点必须**一正一反兼有**，禁止全部同向的彩虹屁或一味唱空 |
| A-5 | **风险红线前置**：若排雷命中红线（清盘预警、经理刚离任、风格严重漂移、暂停赎回、监管处罚等），总览顶部必须以警示条展示，且不可折叠 |
| A-6 | **认知冲突提示**：当板块结论互相矛盾时（如「业绩优秀 + 体验极差」「业绩优秀 + 现任经理刚上任 3 个月」「规模暴增 3 倍 + 策略容量有限」），总览需显式指出矛盾点，这是本产品最有价值的输出之一 |
| A-7 | 总览由模型基于其余板块的**结构化结论**生成，不重新读原始数据，确保不与详情板块冲突 |
| A-8 | 指数/货币基金的总览需自动切换措辞模板：不谈经理能力，改谈跟踪误差/费率/折溢价（附录 C） |

#### 3.3.2 板块②：好业绩 —— 它到底赚不赚钱、靠什么赚

**要回答的问题**：这只基金的收益是真本事还是踩对了风口？能不能持续？

| 子模块 | 优先级 | 关注点 | 输入指标（由计算层提供） |
| --- | --- | --- | --- |
| 长期业绩 | P0 | 拉长看跑得怎么样 | 近 1/3/5 年与成立以来年化收益、同类分位、逐年度收益 |
| 超额来源 | P0 | 是跑赢基准还是跟着市场涨 | 相对基准年化超额、信息比率、与宽基对比、逐年超额正负分布 |
| 业绩稳定性 | P0 | 是「一年神基」还是年年靠前 | 逐年同类排名分位、四分位持续性、是否依赖单一年份 |
| 持仓与风格 | P0 | 赚钱靠什么持仓 | 十大重仓与行业分布、集中度、市值/成长价值暴露、换手率 |
| 归因拆解 | P1 | 行业配置贡献 vs 选股贡献 | 简化 Brinson 归因（数据允许时）、重仓股区间贡献估算 |
| 规模与业绩关系 | P1 | 规模变大后是否失效 | 规模变化曲线与同期超额曲线的对照 |
| 跟踪能力（指数基金专属） | P0 | 跟得紧不紧 | 年化跟踪误差、日均跟踪偏离、与同标的同类基金对比 |

| 编号 | 需求描述 |
| --- | --- |
| B-1 | 输出「能力分 A（0–100）」与标签（优秀/良好/一般/较弱），并给出得分构成的可视化拆解（各子模块小分） |
| B-2 | 必须给出「这只基金的三个亮点」与「三个短板」，数量对称，避免单边叙述 |
| B-3 | 所有结论必须绑定具体数字与**区间**（例：「近 3 年年化 12.4%，同类前 18%；但 2025 年跑输基准 9.2 个百分点」），禁止「业绩优秀」这类无数据支撑的空话 |
| B-4 | 业绩展示必须完整：**不得只展示表现好的区间**，逐年度收益必须全部列出（含亏损年份）；排名必须标注口径（同类分类名 + 样本数 + 截止日） |
| B-5 | 本板块**禁止引用回撤、波动率等风险指标**做正面论证（那是板块 ④ 的职责），从数据切片层面隔离，避免「因为回撤小所以业绩好」的混淆 |
| B-6 | 本板块**禁止出现任何未来收益预测**（含「有望」「预计可达」），亦不得给出「值得长期持有」等结论性建议 |
| B-7 | 与同类对比需以表格呈现（3–5 只），说明选取依据（同二级分类 + 规模相近 + 同期存续）|
| B-8 | 类型差异化模板：指数基金以「跟踪误差 + 费率 + 规模流动性」替代主动选股能力评价；债基强调收益来源拆解（利率/信用/杠杆/转债）；QDII 需剥离汇率影响并单列；成立 < 1 年的基金必须标注结论参考价值有限 |

#### 3.3.3 板块③：好舵手 —— 谁在管，靠不靠谱

**要回答的问题**：钱交给谁了？他管了多久、忙不忙、还在不在、风格稳不稳？

| 子模块 | 优先级 | 关注点 | 输入指标 |
| --- | --- | --- | --- |
| 任职与经验 | P0 | 管这只多久、从业多久、是否经历完整牛熊 | 任职本基金年限、从业年限、任职期间覆盖的市场阶段 |
| 任职期表现 | P0 | 他任内的成绩（而非基金历史成绩） | 任职期间年化、同期基准与同类分位、**任职分段业绩曲线** |
| 精力分配 | P0 | 一拖多、在管规模是否过重 | 在管基金数量、在管总规模、近 1 年新增在管数 |
| 风格一致性 | P0 | 说的和做的是否一致、是否漂移 | 历史持仓风格偏离度、行业轮动频率、换手率变化 |
| 代表作与可迁移性 | P1 | 其他产品是否也管得好 | 代表作历史业绩与同类分位、多产品业绩离散度 |
| 团队与公司支撑 | P1 | 平台是否稳定 | 公司同类基金整体分位、投研团队稳定性、公司处罚记录 |
| 变更历史 | P0 | 换过几任、换手是否频繁 | 历任经理与任期、近 3 年变更次数、当前是否共同管理 |

| 编号 | 需求描述 |
| --- | --- |
| C-1 | 输出「舵手分 M（0–100）」与标签（稳健老将/成长中/新任待观察/频繁更换需警惕） |
| C-2 | **必须明确区分「基金历史业绩」与「现任经理任职期业绩」**，并在净值曲线上标注经理更替时点。若现任经理任职 < 1 年，M 分上限受约束且必须提示「历史业绩主要由前任创造，参考价值有限」 |
| C-3 | 一拖多需给出量化事实与阈值判断（如「在管 12 只、合计 480 亿，同类经理中位为 4 只」），不得仅描述为「较多」 |
| C-4 | 本板块**禁止使用「明星基金经理」「顶流」等营销化措辞**，也禁止对个人做人格化评价（如「稳健可靠的好人」）；只允许基于可核验事实的能力描述 |
| C-5 | 本板块数据切片**不含基金收益排名与净值排行**，仅含任职期区间业绩与同期基准/同类，避免「涨得好=经理牛」的循环论证 |
| C-6 | 已发布经理离任/增聘公告时，必须置顶提示，并说明新任经理的可查信息（若为新人，明示「无可参考的历史业绩」） |
| C-7 | 被动指数与货币基金：本板块降级为「管理团队与运作稳定性」（跟踪能力、团队变更、公司规模），不做能力评分或将 M 分设为不适用（`null`）并说明原因 |

#### 3.3.4 板块④：好体验 —— 我拿着难不难受

**要回答的问题**：这只基金历史上最深跌多少、跌完多久回本、我拿一年大概率是赚还是亏？

| 子模块 | 优先级 | 关注点 | 输入指标 |
| --- | --- | --- | --- |
| 回撤深度 | P0 | 历史上最痛的时候有多痛 | 最大回撤及区间、前 3 大回撤、当前回撤、同类平均回撤对比 |
| 回撤修复 | P0 | 跌下去多久能回来 | 修复天数中位/最长、当前回撤已持续时长 |
| 波动水平 | P0 | 日常颠不颠 | 年化波动率、下行波动率、单日最大跌幅、连续下跌最长天数 |
| 风险调整后收益 | P0 | 承受的波动值不值 | 夏普、卡玛、索提诺，及其同类分位 |
| 持有正收益概率 | P0 | **任意时点买入持有 N 时长赚钱的概率** | 滚动持有 1M/6M/1Y/2Y/3Y 正收益比例、收益分布 P10/中位/P90 |
| 下跌保护 | P1 | 大盘跌时它跌得多不多 | 下行捕获率、上行捕获率、熊市阶段表现（历史分段） |
| 定投平滑效果 | P1 | 分批买的历史结果分布 | 按月定投 12/24/36 期的收益分布（历史模拟，描述性） |

| 编号 | 需求描述 |
| --- | --- |
| D-1 | 输出「体验分 X（0–100）」与标签（平稳/中等波动/较大波动/剧烈波动），并明确说明 **X 分高 ≠ 收益高**，X 衡量的是持有过程的难受程度 |
| D-2 | 回撤必须以**具体数字 + 具体时间段 + 换算成金额**表达，例：「2021-02 至 2022-10 最大回撤 51.3%，投入 10 万元期间最多浮亏 5.13 万元，此后用 14 个月修复」。金额换算固定用 10 万元基准，并注明为历史情形演示、非收益预测 |
| D-3 | 滚动持有正收益概率必须以图表 + 表格双形式呈现，并标注样本区间与样本数；不足 3 年历史的基金需标注样本不足 |
| D-4 | 所有历史模拟（含定投模拟）必须显著标注「历史数据回溯，不代表未来表现，不构成投资建议」，且**禁止表述为「定投更划算」「建议定投」** |
| D-5 | 需与同类平均做对比（回撤、波动、夏普三项至少），让用户知道这个难受程度是普遍现象还是本基金特有 |
| D-6 | 本板块**禁止评价业绩好坏与经理能力**（那是 ②③ 的职责），仅描述波动与持有过程 |
| D-7 | 类型差异化：货币基金聚焦「7 日年化波动 + 是否出现负收益日 + 快赎额度」；债基聚焦「回撤幅度虽小但需看信用事件冲击」；QDII 需说明汇率与交易日差异带来的额外波动 |

#### 3.3.5 板块⑤：好时机与成本 —— 现在贵不贵、我要花多少钱

**要回答的问题**：它的持仓现在贵不贵？规模与限购是否影响运作？我持有一年要付多少费？

| 子模块 | 优先级 | 关注点 | 输入指标 |
| --- | --- | --- | --- |
| 持仓估值位置 | P0 | 它买的东西现在贵不贵 | 重仓加权 PE/PB 的近 3/5 年历史分位、重仓行业估值分位 |
| 净值位置 | P0 | 离历史高点多远、处在什么位置 | 距历史最高净值幅度、近 1/3 年净值分位、近期涨幅 |
| 赛道拥挤度 | P1 | 是不是人人都在买的热门 | 主题/行业公募配置比例分位、近期规模增速、同主题基金数量增长 |
| 规模与容量 | P0 | 规模是否影响策略、是否限购 | 规模及变化、迷你基/巨无霸判断、申购状态与限额、赎回状态 |
| 费率与成本 | P0 | 我要付多少 | 管理+托管+销售服务费、申赎费阶梯、**持有 1 月/6 月/1 年/3 年总成本测算**、A/C 类成本对照、同类费率分位 |
| 折溢价（场内专属） | P0 | 买场内会不会买贵 | 折溢价率及历史分位、成交额与流动性、QDII 溢价风险提示 |
| 流动性与交易规则 | P1 | 想卖能不能卖、几天到账 | 日均成交额（场内）、赎回到账时间、最短持有期、快赎额度 |

| 编号 | 需求描述 |
| --- | --- |
| E-1 | 输出「时机成本分 T（0–100）」与标签（位置偏低/中性/位置偏高/成本偏高），并展示「估值位置」与「成本」两部分权重 |
| E-2 | 估值必须以**分位**表达而非绝对值优劣（PE 30 倍对不同行业含义不同），并展示估值历史分位带状图；主动基金需说明该估值基于最新季报持仓（滞后性提示） |
| E-3 | 费率测算必须给出**可核对的计算过程**（费率项 × 持有期 + 申赎费），并声明测算基于公开费率、不含平台折扣差异 |
| E-4 | A/C 类对比只允许陈述成本事实（如「持有 7 个月以内 C 类总成本更低，超过 8 个月后 A 类更低（按当前费率与常见折扣测算）」），**禁止出现「建议选 C 类」** |
| E-5 | 场内溢价超过阈值（如 QDII 溢价 > 5%）必须以警示形式展示，说明溢价回归风险，并同步进入板块 ⑥ |
| E-6 | 本板块**禁止评价基金好坏与经理能力**，也**禁止出现买入时点、加仓、抄底、择时建议**等操作性表述（合规红线，见 3.8） |
| E-7 | 类型差异化：债基以「久期与利率环境」替代持仓估值分位；货币基金只保留费率与流动性；指数基金需强调费率对长期收益的影响幅度（可量化陈述） |

#### 3.3.6 板块⑥：风险排雷

**要回答的问题**：有什么我可能没看见、但一旦发生就很痛的问题？

| 风险类别 | 优先级 | 排查项 |
| --- | --- | --- |
| 风格漂移风险 | P0 | 实际持仓与合同约定范围偏离；行业分布与历史 4–8 期显著偏离；主题基金重仓非主题股票；换手率突增；「名不符实」（名称含赛道但持仓不符） |
| 存续与清盘风险 | P0 | 规模 < 5000 万（及连续天数）、连续 60 个工作日持有人不足 200 人或规模不足的合同终止条款、已发清算/清盘提示公告、发起式基金 3 年到期考核 |
| 人员变动风险 | P0 | 现任经理任职 < 6 个月、近 3 年更换 ≥ 3 次、已发离任/增聘公告、共同管理中主基金经理离任、公司投研团队大规模变动 |
| 规模与容量风险 | P0 | 规模短期暴增（如 1 季度 > 200%）导致策略容量失效、小盘策略规模过大、巨无霸基金调仓困难、暂停/大额限购影响正常运作 |
| 持有人结构风险 | P0 | 机构持有 > 70%、单一持有人 > 20%/50%（大额赎回冲击净值与被迫调仓）、近期份额大幅缩减 |
| 集中度与踩雷风险 | P0 | 前十大集中度过高（如 > 70%）、单一行业占比过高、重仓股出现 ST/退市风险/停牌/暴跌、重仓债违约或评级下调 |
| 收益异常风险 | P0 | 净值与业绩基准长期背离、债基收益显著高于同类（隐含信用下沉或杠杆）、单日净值异常跳变（可能为估值调整或分红处理） |
| 交易与流动性风险 | P1 | 场内日均成交额过低、折溢价异常、QDII 高溢价与限额、赎回到账慢、最短持有期锁定 |
| 合规与治理风险 | P1 | 基金公司或经理涉监管处罚/立案、涉诉、基金合同重大变更、托管人变更、评级下调 |
| 市场系统性风险 | P1 | 宽基估值处于高分位、所属赛道处于下行周期、Beta 过高、利率环境对债基不利、汇率对 QDII 不利 |
| 信息透明度风险 | P2 | 季报披露信息过少、持仓披露仅十大（隐形持仓不可见）、数据缺失导致多个子模块不可用 |

| 编号 | 需求描述 |
| --- | --- |
| R-1 | 每条雷点必须包含四要素：**风险描述 + 触发依据（具体数值/公告标题与日期） + 严重程度（高/中/低） + 关注建议（如「关注下季报持仓是否回归约定范围」）**，严禁「投资有风险请注意」这类无信息量条目 |
| R-2 | 采用**规则引擎 + 模型解读**双层：先由确定性规则按阈值扫描候选雷点（可审计、可回归测试），再由模型解释「为什么这是问题、会怎么演化」。**禁止模型自行新增未经规则触发的雷点** |
| R-3 | 输出总体风险等级：🔴 红（存在高严重度雷点或触发硬红线）/ 🟡 黄（存在中等风险）/ 🟢 绿（未发现显著异常），并说明判定原因 |
| R-4 | **硬红线清单**（命中即红，且总览必须警示）：已发清盘/清算提示公告、规模连续低于合同终止阈值、暂停赎回、现任经理任职 < 3 个月且前任已离任、风格漂移达严重级（重仓与约定范围偏离超阈值）、单一持有人 > 50%、QDII/LOF 溢价 > 10%、基金公司或经理被立案调查 |
| R-5 | 「未发现风险」不等于「安全」：绿灯文案必须写明「基于已获取的公开数据，未发现以下 N 类异常」，列出实际检查项与数据完整度 |
| R-6 | 风险阈值需**可配置**（配置文件而非硬编码），且支持**按基金类型差异化**（债基负债/杠杆阈值、指数基金跟踪误差阈值、货币基金规模阈值与权益基金完全不同，不应误报） |
| R-7 | 雷点按严重程度降序展示；移动端默认展开高严重度，中低严重度可折叠为「查看其余 N 项」 |
| R-8 | 风格漂移检测需给出**可视化证据**：合同约定范围、历史 4 期行业分布堆叠图、最新一期偏离项高亮，而非仅一句结论 |

#### 3.3.7 评分体系与呈现（P0）

| 编号 | 需求描述 |
| --- | --- |
| S-1 | 五个独立输出：能力分 **A**、舵手分 **M**、体验分 **X**、时机成本分 **T**（均 0–100）、风险等级 **R**（红/黄/绿）。**不做单一综合总分**，避免用一个数字掩盖矛盾 |
| S-2 | 以**四维雷达图**（A/M/X/T）+ 风险灯呈现，替代股票产品的二维象限。理由：基金的矛盾组合多于两两组合（如「业绩好但体验差且刚换人」） |
| S-3 | 典型组合需有固定描述文案（描述性，非建议性），至少覆盖：<br>▸ A 高 + X 低 → 「长期业绩靠前，但历史波动与回撤显著高于同类」<br>▸ A 高 + M 低 → 「历史业绩主要由前任经理创造，现任任职时间较短」<br>▸ A 高 + T 低 → 「业绩与持仓质地较好，但持仓估值处于历史高分位、且费率高于同类」<br>▸ A 低 + X 高 → 「波动较小，但长期收益同样落后于同类」<br>▸ 任一维度 + R 红 → 风险主导语气，其余结论必须让位 |
| S-4 | 文案必须为**描述性**而非建议性，禁止「可买入 / 建议规避 / 值得定投」等表述 |
| S-5 | 风险等级为红时，雷达图叠加红色警示边框，总览结论必须以风险为主导语气 |
| S-6 | 评分规则页面可查看（每个子模块权重与打分口径、按基金类型的权重差异），并声明「评分为程序化数据描述，非投资建议、非评级」。**不得使用「五星」「金牛」等易与官方评级混淆的符号** |
| S-7 | 同一基金同一净值日重复分析，A/M/X/T 波动应 ≤ 5 分（可复现性要求）；实现上对模型输出的分数做区间约束与规则校验 |
| S-8 | 类型不适用的维度显式置为 `null` 并说明原因（如被动指数基金的 M 分），前端雷达图对应轴灰显，**不得用 0 分或默认 60 分代替** |

#### 3.3.8 生成编排与工程要求

| 编号 | 需求描述 |
| --- | --- |
| F3-1 | **先算后说**：所有数值由后端确定性代码计算完成后再交给模型解读，禁止模型自行做数值计算或推算 |
| F3-2 | **六板块编排**：②③④⑤⑥ 五个板块**并行**调用模型（各自独立 Prompt 与独立数据切片），全部返回后以其结构化结论作为输入生成 ① 总览。既降低单次上下文长度，也保证板块正交 |
| F3-3 | 并发与成本控制：单次分析 6 次模型调用，需按网关并发限制做队列；若网关并发不足，允许合并为「②③ 一组、④⑤ 一组、⑥ 单独」共 4 次调用（配置项 `AI_MERGE_STRATEGY`），但数据切片隔离规则不变 |
| F3-4 | 模型必须返回结构化 JSON（`score`/`level`、`tag`、`summary`、`modules[]`、`evidence[]`），前端按结构渲染，不直接渲染模型原始 Markdown |
| F3-5 | 每条结论需附带 `evidence`（引用的具体数据项、数值、区间/报告期、来源），前端以「依据」可展开形式呈现 |
| F3-6 | **数字回校验**：对模型输出中的数字与计算层结果比对，不一致则丢弃该条结论并记录日志，防止幻觉数字流向用户 |
| F3-7 | **类型路由**：入口按基金类型选择板块模板与 Prompt 变体（附录 C），并把「不适用的子模块」从数据切片中移除，而不是让模型自行判断 |
| F3-8 | 流式输出（SSE）：板块按完成顺序上屏，前端以骨架占位（总览生成中 → 好业绩 → 好舵手 → 好体验 → 好时机与成本 → 风险排雷），总览完成后回填至顶部 |
| F3-9 | **合规过滤**：命中「买入/卖出/加仓/减仓/抄底/建议定投/值得买/必涨/稳赚/收益可达/明星基金经理/推荐」等词汇时改写为中性表述并记录日志（基金禁用词库比个股更长，见附录 B） |
| F3-10 | 分析深度：`快速`（六板块的 P0 子模块，约 25s）/ `深度`（含全部 P1 子模块、同类对比、归因与定投模拟，约 45s），默认快速 |
| F3-11 | 板块级降级：单板块模型超时（默认 45s）或返回非法 JSON 时重试 1 次；仍失败则降级为「规则版结论」（纯指标 + 规则文案）并标注 `generatedBy=rules`，其余板块不受影响；总览在缺板块时仍需生成并说明缺失内容 |
| F3-12 | 报告快照固定：报告生成后内容不随净值变化而改变，页面显示「净值日期 / 持仓报告期 / 生成时间」三个时间戳 |
| F3-13 | 多视角圆桌（P2）：总览下方增设「长期派 / 交易派 / 风控派」对同一基金的分歧陈述，本质是把 ②④⑥ 拟人化表达，增强可读性 |

## 4. 多端适配需求（核心诉求之二）

### 4.1 总体策略

**一套代码、响应式布局、移动优先**。以移动端布局为基准编写样式，通过断点向上增强为桌面端；不做 UA 判断跳转独立 m 站，避免双份维护与分享链接错端问题。

### 4.2 断点定义

| 断点名 | 宽度范围 | 典型设备 | 布局形态 |
| --- | --- | --- | --- |
| xs | < 480px | 小屏手机 | 单列，卡片全宽，底部操作栏 |
| sm | 480–767px | 主流手机 | 单列，间距放大 |
| md | 768–1023px | 平板 / 折叠屏展开 | 两列卡片网格 |
| lg | 1024–1439px | 笔记本 | 左内容 + 右侧信息栏与锚点导航 |
| xl | ≥ 1440px | 桌面大屏 | 内容区定宽居中（最大 1440px），三区布局 |

### 4.3 关键页面的双端形态

| 页面 / 板块 | 桌面端（≥1024px） | 移动端（<768px） |
| --- | --- | --- |

### 5.2 安全

| 编号 | 需求描述 |
| --- | --- |
| S-1 | 所有第三方数据源与大模型接口地址走**白名单**配置；服务端出网请求禁止访问内网地址段与回环地址（含 9/10/11/21/30 段），DNS 解析后校验 IP，不跟随重定向，防 SSRF |

| S-6 | 分享报告链接使用不可枚举 ID（随机串），避免遍历他人报告 |
| S-7 | 接口层限流（IP + 设备维度）与异常请求熔断；模型调用设日预算熔断，防止刷接口拉高成本 |

## 6. 技术方案建议（供评审，非最终约束）

```
[浏览器：响应式 Web（桌面 + 移动同一套代码）]
      │  HTTPS
      ▼
[Node.js / Express 服务]
      ├─ 搜索与标的解析（本地基金字典 + 份额分组，定时更新）
      ├─ 类型路由（权益/指数/债/QDII/FOF/货币 → 模板与切片选择）
      ├─ 数据采集层（公开净值/持仓/经理/公告/费率接口 + 多源互备 + 缓存 + 降级）
      ├─ 指标计算层（确定性：区间年化、回撤族、波动族、滚动持有概率、
      │              估值分位、费率成本、漂移偏离度、跟踪误差）
      ├─ 风险规则引擎（阈值可配置 + 按基金类型差异化，40+ 条规则）
      ├─ AI 编排层
      │     ├─ 并行：好业绩 / 好舵手 / 好体验 / 好时机与成本 / 风险排雷
      │     └─ 汇总：总览（输入为上游五块的结构化结论）
      │     └─ JSON 校验 → 数字回校验 → 合规过滤 → SSE 流式下发
      ├─ 报告服务（落库 + 只读分享页 + 快照固定）
      └─ 限流 / 配额 / 日志 / 健康检查 / 日预算熔断
      ▼
[存储：SQLite（分析记录/报告/配额/规则命中） + 文件（报告快照、净值缓存）]
```

**选型建议与理由**

| 层 | 建议 | 理由 |
| --- | --- | --- |
| 前端 | 原生 HTML/CSS/JS + CSS Grid/Flex + 容器查询 | 首屏轻、无需复杂状态管理，利于移动端体积控制；与同域名下 `stockAnalysis` 一致，样式与组件可复用 |
| 图表 | ECharts（按需引入折线/柱线/雷达/堆叠图） | 移动端手势支持完善，雷达图与水下图开箱可用 |
| 后端 | Node.js + Express | 与现有同类项目一致，运维统一 |
| 取数 | Node 直连公开接口为主；复杂筛选/清洗可复用 Python 脚本（子进程 + 参数数组调用） | 参考 `fundRecommend` 项目经验：天天基金公开接口需带 `Referer`，且部分接口为 JSONP 需清洗 |
| 大模型 | 通过统一网关调用（模型可配置切换），超时 45s，结构化 JSON 输出 | 便于成本与稳定性调优；六板块并行需确认网关并发限制（见 F3-3 合并策略） |
| 存储 | SQLite（better-sqlite3）+ 本地文件（报告快照、净值序列缓存） | 一期数据量小，运维成本最低；原生模块不可用时降级为 JSON 文件存储 |
| 部署 | PM2 + Nginx 反代到子路径 `/fundAnalysis/`（HTTPS 终止在 Nginx，SSE 需关闭 `proxy_buffering`） | 与现有站点复用同一域名与证书；端口建议 **3250**（避开已用的 3000/3030/3100/3210/3220/3240） |

## 8. 验收标准（可测试）

**功能类（六板块）**

1. 输入 `白酒`、`161725`、`zsbj` 三种形式，均能命中「招商中证白酒指数」，且下拉中 A/C 份额分组展示、不自动选择。
2. 对任一主动权益基金发起深度分析，报告必须包含且仅包含六大板块，顺序为 总览 → 好业绩 → 好舵手 → 好体验 → 好时机与成本 → 风险排雷。
3. 「好业绩」板块输出 A 分与全部 P0 子模块，逐年度收益**完整列出含亏损年份**，排名标注分类/样本数/截止日；全文不出现回撤、夏普等风险指标作为正面论证。
4. 「好舵手」板块的净值曲线正确标注经理更替时点；对一只现任经理任职 < 1 年的基金，必须出现「历史业绩主要由前任创造」提示，且 M 分受上限约束。
5. 「好体验」板块的最大回撤、修复时长、滚动持有 1 年/3 年正收益概率数值与独立脚本复算结果一致（误差 ≤ 0.1 个百分点）；回撤含 10 万元金额换算与「非收益预测」标注。
6. 「好时机与成本」板块的费率总成本测算过程可展开核对；对一只 C 类份额基金，A/C 成本对照表出现且**不含「建议选择」类表述**。
7. 「风险排雷」对一只已知风格漂移或单一持有人占比 > 50% 的基金能正确扫出雷点，四要素（描述/触发依据/严重度/关注建议）完整；对一只健康基金返回绿灯，文案写明「已检查 N 类异常」并给出 N 的实际值。
8. 命中硬红线（如已发清盘提示公告的基金）：风险等级为红，总览顶部出现不可折叠警示条，总览语气不呈现单纯乐观。
9. 类型自适应：对一只被动指数基金，M 分为 `null` 且雷达图对应轴灰显并说明原因；「好业绩」板块出现跟踪误差子模块。对一只货币基金，不出现持仓估值分位与经理能力评分。
10. 结论一致性：总览要点与五个详情板块不矛盾（人工抽检 20 份报告，矛盾率为 0）。
11. 可复现性：同一基金同一净值日连续分析 3 次，A/M/X/T 极差 ≤ 5。
12. 幻觉防护：人为在模型返回中植入与计算层不符的数字，该条结论被丢弃且日志有记录。

**降级与容错类**

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 公开数据接口不稳定或变更（净值、持仓、经理） | 分析质量下降甚至不可用 | 数据源抽象为适配器，配置化切换；多源互备；全链路缓存兜底；板块级降级；`DATA_MODE=auto/live/mock` 保证任何环境可运行并显著标注演示数据 |
| **持仓数据天然滞后（季报，最长滞后近 4 个月）** | 「持仓估值」「风格漂移」结论可能失真 | 所有持仓类结论强制标注报告期与滞后天数；漂移检测以「多期趋势」而非单期结论；报告显式说明隐形持仓不可见 |
| **净值复权处理错误（分红、拆分）** | 收益与回撤全部算错，是本产品最致命的数据坑 | 统一使用复权净值口径；对分红/拆分日做跳变检测（单日涨跌幅绝对值超阈值且当日有分红记录时自动校正）；用第三方公布的区间收益做交叉校验，偏差 > 0.5 个百分点即告警 |
| 基金类型异质性导致模板爆炸 | 债基/货币/QDII 出现大量不适用结论 | 类型路由 + 切片白名单（附录 C）；不适用维度显式 `null` 并说明；一期优先保证权益类与指数类质量，债/QDII/FOF 走精简模板 |
| 大模型幻觉（编造数值、编造经理履历） | 用户信任崩塌 | 数值一律由后端计算后喂给模型；强制 `evidence` 引用；数字回校验不一致即丢弃；**经理履历与公告类事实只允许引用抓取到的原文字段，不允许模型补全** |
| 板块正交被破坏（好业绩板块引用回撤、好舵手板块引用收益排名） | 循环论证，结论失真 | 从**数据切片层**隔离，Prompt 只能看到自己的切片；评审与用例作为硬性检查项 |
| 风险规则误报/漏报（债基阈值套用到权益基金） | 用户被错误惊吓或错过真雷 | 阈值按基金类型可配置；每条规则配回归用例（已知漂移基金/清盘基金/健康基金样本集）；绿灯文案明确「仅覆盖已检查的 N 类」 |
| 评分被当作推荐或评级 | 合规与预期风险 | 不给单一总分；四刻度 + 风险灯；文案纯描述性；规则页面公开口径并声明非评级；不使用星级符号 |
| **合规风险（被认定为基金推荐或销售）** | 产品下线风险 | 不做榜单、不做推荐、无购买入口；禁用词库过滤；业绩展示合规（完整年度、同期基准、排名口径、不满 6 个月不展示排名）；不预测收益 |
| 模型调用成本超预算（六板块 = 6 次调用） | 不可持续 | 缓存优先（同基金同净值日复用）；快速模式减少子模块；`AI_MERGE_STRATEGY` 支持合并为 4 次；Token 用量监控与日预算熔断 |
| 双端体验割裂（图表在手机上不可读） | 移动端流失 | 移动优先开发；每个板块评审时必须同时演示两端；五视口检查纳入验收；图表在 375px 下有独立精简形态而非等比缩小 |
| 分析耗时过长导致用户流失 | 转化率低 | 五板块并行 + 流式上屏 + 骨架占位 + 首个板块 15s 内可见 |

## 附录 C：基金类型差异化矩阵（实现必读）

「适用」= 正常输出；「精简」= 仅 P0 子模块；「替代」= 换成括号内维度；「不适用」= 板块置 `null` 并说明原因。

| --- | --- | --- | --- | --- | --- |
| 主动权益（股票型/偏股混合） | 适用（全量） | 适用（全量） | 适用（全量） | 适用（全量） | 风格漂移、规模容量、经理变动、集中度 |

| 混合偏债 / 二级债基 | 适用（拆分股债贡献） | 适用 | 适用 | 精简 | 股债比例漂移、转债占比过高 |
